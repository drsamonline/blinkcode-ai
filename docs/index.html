What it does

An optical link that lives entirely in the browser

Every capability below is implemented in the repository — no placeholder buttons, no hidden server.

One-time model, then offline

The compression model downloads once into Cache Storage + IndexedDB. After that the app is fully offline — no runtime CDN, no network needed to move a file.

Lossless File DNA

An order-1 context model plus arithmetic coder packs any file type losslessly into a compact container — text, JSON and source code typically shrink ~2–4×.

SpectraCode rendering

A 36-colour palette paints payload cells inside bullseye markers and a calibration strip, so the receiver can lock geometry and correct colour.

Error correction built in

Reed–Solomon RS(255,223) corrects up to 16 bytes per block, and every frame carries a CRC-32 so the receiver knows exactly what it has collected.

Continuous camera auto-scan

Marker detection feeds a homography and a 3×4 colour-correction fit, then cells are classified — with a wake lock held while a code is displayed.

Streaming frames

Larger files loop as a numbered frame sequence with a chunk header and out-of-order collection — the receiver shows how many frames it still needs.

How it works

Compress → paint → scan → decode

Small payloads fit in a single static frame. Larger ones loop as a numbered frame sequence the receiver collects while scanning.

1

Compress

Pick a file (or paste text) and hit Compress. The coder turns it into a File DNA container.

2

Show

Show SpectraCode paints the container as colour cells on the sender's screen.

3

Scan

The receiver hits Start scanning and points its camera at the sender's screen.

4

Decode

Frames are collected, verified by CRC-32 and decoded back to the original file.

Get started

Run it locally in three commands

No build step and no runtime dependencies — a static dev server with the headers the PWA needs.

# (re)train and package the model bundle
npm run build:model

# http://localhost:8080
npm run serve

# codec + full optical loopback tests
npm test

Open the app, pick a file (or paste text), hit Compress, then Show SpectraCode on the sender and Start scanning on the receiver. The receiver decodes continuously and shows how many frames it still needs.

No second device? The loopback self-test button pushes every rendered frame back through the real optical decoder.

FAQ

Honest answers

These limits matter more than the pitch, so they are stated plainly here and in the app's own "How it works" tab.

How much fits in one SpectraCode frame?

One frame holds 5,111 payload bytes at standard density (1,097 in robust density): 120×80 cells × 5 bits = 6,000 bytes raw, minus Reed–Solomon parity and the 18-byte frame header. Bigger files are split across frames, so throughput is roughly 5 KB × frame rate — about 15 KB/s at 3 frames per second, and every missed frame costs a full loop.

Is the compression really 1000:1?

Not for arbitrary files — and it cannot be. Lossless coding cannot go below the entropy of the data; a universal 1000:1 compressor would let you recurse to one byte. Real measured ratios are ~2–4× on text, JSON and source code, and roughly 1× (slight expansion) on already-compressed data such as JPEG, ZIP or MP4. Extreme ratios only exist in perceptual mode, which is genuinely lossy.

What is perceptual mode?

It is a lossy image path: an image becomes a 64-value, 8-bit quantised latent and comes back as a soft, 32×32-detail reconstruction. That is a 1000:1+ ratio — and a very different picture.

Is the "neural" model a real neural network?

The bundle format, one-time download, offline caching and the coder's model API are production-shaped, but the weights inside are trained order-1 byte statistics plus DCT quantiser scales (~129 KB), not a 50 MB neural net. It is a mock with a real interface: Order1Model in src/lib/arith.js and the transforms in src/lib/image-codec.js are the two swap points for a real learned predictor or autoencoder. TensorFlow.js is intentionally not bundled — no runtime CDN dependency is allowed.

Has camera decoding been tested on a real phone?

It is validated in simulation: the test suite renders a code, applies perspective tilt, a colour cast and vignetting, and decodes it end to end. Real-world glare, motion blur and low-end camera sensors are what the robust density exists for; they may still need per-cell voting and multi-frame averaging.
