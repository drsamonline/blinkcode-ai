Point your camera, get the file.

BlinkCode compresses a file into a File DNA container, paints it as SpectraCode colour matrices, and recovers it by pointing a camera at the sender's screen. No server, no network after the first launch.

What it does

Colour, not black and white

36 reference colours, five bits per cell — a single SpectraCode frame holds kilobytes where a QR holds hundreds of bytes.

Real compression

An order-1 arithmetic coder with a match (LZP) model, plus a lossy perceptual image mode for photos.

Built to survive

Reed–Solomon RS(255,223) repairs up to 16 damaged bytes per block; the decoder fits a colour-correction matrix from a calibration strip.

Offline-first PWA

The model bundle downloads once and is cached. After that the app never touches the network.

How it works

send file ─▶ arithmetic coder ─▶ File DNA ─▶ frames ─▶ RS(255,223) ─▶ colour grid receive camera ─▶ bullseye detect ─▶ homography ─▶ colour correction ─▶ classify ─▶ RS ─▶ collector ─▶ CRC-32 ─▶ arithmetic decoder ─▶ file

The four bullseyes are how the decoder finds the frame and its perspective; the calibration strip is how it learns what this screen's colours actually are before it reads a single cell.

What it will not do

It will not replace the network. It is for the case where two devices are in the same room and neither can reach the other: a file, a screen, a camera, and nothing in between. Large files stream as several frames, so the transfer takes as long as it takes.
